## Bug 1: `MODEL_PATH` 未定义

**报错**
```
NameError: name 'MODEL_PATH' is not defined
```

**位置**
`omni_vla/src/openpi/models_pytorch/vlm_with_spatial.py:174`

**原因**
`VLMWithSpatialActionExpertModel.__init__` 有 `vlm_pretrained_path` 参数，但代码内部误用了未定义的全局变量 `MODEL_PATH`。

**修复**
```python
# 修改前
state_dict = load_file(MODEL_PATH, device="cpu")

# 修改后
state_dict = load_file(vlm_pretrained_path, device="cpu")
```

## Bug 2: `vlm_pretrained_path` 为 None（调用方未传参）

**报错**
```
TypeError: argument 'filename': expected str, bytes or os.PathLike object, not NoneType
```

**位置**
`omni_vla/src/openpi/models_pytorch/omni_vla.py:154`

**原因**
`OmniVLA.__init__` 创建 `VLMWithSpatialActionExpertModel` 时未传入 `vlm_pretrained_path` 和 `vggt_pretrained_path`，导致它们默认为 `None`。这两个路径定义在 `OmniConfig` 中。

**修复**
```python
# 修改前
self.reasoning_spatial_expert = VLMWithSpatialActionExpertModel(
    paligemma_config,
    spatial_config,
    action_expert_config,
    precision=config.dtype,
)

# 修改后
self.reasoning_spatial_expert = VLMWithSpatialActionExpertModel(
    paligemma_config,
    spatial_config,
    action_expert_config,
    vlm_pretrained_path=config.vlm_pretrained_path,
    vggt_pretrained_path=config.vggt_pretrained_path,
    precision=config.dtype,
)
```

## Bug 4: FSDP 混合 `requires_grad` 报错

**报错**
```
ValueError: Must flatten tensors with uniform `requires_grad` when `use_orig_params=False`
```

**位置**
`rlinf/hybrid_engines/fsdp/strategy/fsdp.py:80`，FSDP 初始化时

**原因**
模型部分参数被冻结（`requires_grad=False`），部分可训练（`requires_grad=True`），但 FSDP 配置 `use_orig_params=False` 要求同一 flat param 组内所有参数的 `requires_grad` 一致。

**修复**
在 `examples/embodiment/config/libero_spatial_ppo_omni_vla_quickstart.yaml` 的 `fsdp_config` 中添加：
```yaml
fsdp_config:
  use_orig_params: True   # 新增
```

## Bug 5: `GemmaModel` 没有 `.model` 属性

**报错**
```
AttributeError: 'GemmaModel' object has no attribute 'model'
```

**位置**
`rlinf/models/embodiment/omni_vla/omni_vla_action_model.py:604`，以及
`omni_vla/src/openpi/models_pytorch/vlm_with_spatial.py` 中多处

**原因**
代码假设 `PaliGemmaForConditionalGeneration.language_model` 是 `GemmaForCausalLM`（需要再通过 `.model` 访问 `GemmaModel`），但项目使用的自定义 PaliGemma 实现（`transformers_replace`）中用 `AutoModel.from_config` 创建语言模型，返回的直接是 `GemmaModel`，少一层 `.model`。

同时，权重 key 映射也存在多余的 `.model.` 层级。

**修复1 - 权重 key 映射**（`vlm_with_spatial.py`）：
```python
# 修改前
return "language_model.model." + key[len("model.language_model."):]

# 修改后
return "language_model." + key[len("model.language_model."):]
```

**修复2 - 运行时属性访问**（`vlm_with_spatial.py` 多处 + `omni_vla_action_model.py`）：
```python
# 修改前（示例）
reasoning_expert.language_model.model.layers[layer_idx].self_attn

# 修改后
reasoning_expert.language_model.layers[layer_idx].self_attn
```
涉及文件：
- `vlm_with_spatial.py`: 第 64、96、99、107、108 行（全局替换 `reasoning_expert.language_model.model.` → `reasoning_expert.language_model.`）
- `omni_vla_action_model.py`: 第 604 行
