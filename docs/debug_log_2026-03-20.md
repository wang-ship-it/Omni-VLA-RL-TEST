## Bug 15: `explained_variance` 计算导致 NaN

**问题描述**
训练过程中 `explained_variance` 日志输出为 `NaN`，导致 W&B 等监控显示异常。

**原因分析**
1. `loss_mask` 过滤掉 padding steps 后，剩余有效样本可能只有 1-4 个
2. `chunk_level` flatten 操作进一步消耗样本
3. `torch.var(unbiased=True)` 在样本数 < 2 时返回 NaN
4. 原代码未对 NaN/Inf 进行过滤，且 `ev_source` fallback 逻辑存在问题

**涉及文件**
- `rlinf/algorithms/losses.py` — `compute_ppo_critic_loss` 函数

**修复内容**

原始代码（line 346-382，原版本）：
```python
ev_source = "masked"
ev_returns = masked_returns
ev_values = masked_values
if valid_count < 2:
    ev_source = "unmasked_fallback"
    ev_returns = returns.reshape(-1)
    ev_values = values.reshape(-1)
    ...

var_returns_unbiased = torch.var(ev_returns)  # n<2时为NaN
var_returns = torch.var(ev_returns, unbiased=False)

if not torch.isnan(var_returns) and var_returns > var_eps:
    var_diff = torch.var(ev_returns - ev_values, unbiased=False)
    if not torch.isnan(var_diff):
        explained_variance = 1 - var_diff / var_returns
        ev_valid = True
    # 问题：else分支没有设置explained_variance，保持NaN
```

修复后代码：
```python
ev_returns = masked_returns
ev_values = masked_values
valid_mask = torch.isfinite(ev_returns) & torch.isfinite(ev_values)
ev_returns = ev_returns[valid_mask]
ev_values = ev_values[valid_mask]

var_eps = 1e-8
if ev_returns.numel() < 2:
    explained_variance = torch.tensor(0.0, device=returns.device)
    ev_valid = False
else:
    var_returns = torch.var(ev_returns, unbiased=False)

    if torch.isfinite(var_returns) and var_returns > var_eps:
        var_diff = torch.var(ev_returns - ev_values, unbiased=False)

        if torch.isfinite(var_diff):
            explained_variance = 1 - var_diff / var_returns
            ev_valid = True
        else:
            explained_variance = torch.tensor(0.0, device=returns.device)
            ev_valid = False
    else:
        explained_variance = torch.tensor(0.0, device=returns.device)
        ev_valid = False
```

**修复要点**
1. 新增 `torch.isfinite()` 过滤 NaN/Inf，避免传染
2. 统一使用 `biased` 方差（`unbiased=False`），样本少时更稳定
3. 所有失败分支明确返回 `0.0`，不再产生 NaN
4. 删除 `ev_source` fallback 到 unmasked 的无效逻辑

**metrics_data 变更**
```python
# 删除了这一行（ev_source已删除）
# "critic/explained_variance_source_masked": 1.0 if ev_source == "masked" else 0.0,
```

## Bug 16: `freeze_vggt` / `freeze_spatial_expert` 配置项无效

**问题描述**
YAML 配置文件中存在 `freeze_vggt: True` 和 `freeze_spatial_expert: True` 参数，但实际运行时这些模块已被硬编码冻结，配置参数不起作用。

**涉及文件**
- `omni_vla/src/openpi/models_pytorch/omni_vla.py` — `__init__` 和 `set_requires_grad` 方法
- `examples/embodiment/config/libero_spatial_ppo_omni_vla_quickstart.yaml`

**代码分析**

`omni_vla.py` 的 `__init__` 方法中存在硬编码冻结（line 189-197）：
```python
# Hardcoded freeze — 无论配置如何都会执行
for param in self.reasoning_spatial_expert.vggt_encoder.parameters():
    param.requires_grad = False

for param in self.reasoning_spatial_expert.reasoning_expert.vision_tower.parameters():
    param.requires_grad = False
```

`set_requires_grad()` 方法虽然读取配置参数（line 217-234）：
```python
def set_requires_grad(self):
    freeze_vggt = getattr(self.config, "freeze_vggt", False) or getattr(self.config, "freeze_VGGT_model", False)
    if freeze_vggt:
        self.reasoning_spatial_expert.vggt_encoder.eval()
        for p in self.reasoning_spatial_expert.vggt_encoder.parameters():
            p.requires_grad = False
```

但由于 `__init__` 已经在更早阶段硬编码冻结，配置参数的逻辑永远不会执行到。

**冻结状态总结**

| 模块 | 冻结方式 | 配置参数是否生效 |
|------|---------|----------------|
| VGGT encoder | `__init__` 硬编码 | ❌ 否（hardcoded在前） |
| vision_tower | `__init__` 硬编码 | ❌ 否（hardcoded在前） |
| spatial_expert | `__init__` 硬编码（已注释） | ⚠️ 需确认 |
| reasoning_expert | `set_requires_grad()` 读取配置 | ✅ 是（如果调用） |

**修复内容**
1. 从 YAML 配置中删除注释掉的 `freeze_vggt` 和 `freeze_spatial_expert` 行
2. 这些参数本身无效，保留会造成困惑

## Bug 17: 只走 base model hidden，不算 logits（不走 lm_head）

**问题描述**
PPO 的 value 分支只需要 hidden states；如果走到 logits/lm_head，会引入不必要的显存和计算开销，并干扰 value 路径排查。

**涉及文件**
- `omni_vla/src/openpi/models_pytorch/vlm_with_spatial.py`
- `rlinf/models/embodiment/openvla/openvla_action_model.py`
- `rlinf/models/embodiment/openvla_oft/rlinf/openvla_oft_action_model.py`

**关键实现**
1. `compute_values=True` 时强制 `output_hidden_states=True`，从 `hidden_states[-1]` 取特征进入 `value_head`。
2. 在 OmniVLA/VLM spatial 路径中，使用 `last_hidden_state` 或 `hidden_states[-1]` 继续后续计算，不依赖 `lm_head` logits。

**结论**
value/critic 路径按“base hidden-only”执行，符合 PPO 训练需求；该改动用于降低不必要开销并稳定训练排查。
